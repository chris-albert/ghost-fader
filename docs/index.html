Sheet 0 · How it works

Each input goes through a differential line receiver that turns the balanced pair into a clean single-ended signal and rejects cable noise. A plain TS plug just grounds the cold side, so unbalanced sources work with no switch. From there the two signals feed four digitally controlled attenuators arranged as a 2×2 matrix: any input can reach either output at any level. Two op-amp summers add the contributions, and cross-coupled balanced drivers put a true balanced signal on each output jack.

The XIAO RP2040 shows up on the computer as a class-compliant USB MIDI device, works out four gains from volume, pan, and whether the R jack has a plug in it, and writes them over SPI. Because pan and mono-to-stereo are just numbers in the matrix, there is no analog routing switch, no relay click, and a stereo source can be balanced or genuinely image-shifted. The same USB cable powers the box: an isolated DC-DC module turns the 5 V bus into the ±12 V analog rails.

Why these parts

  • PGA2310, not a digital pot. Digital pots run on 5 V and clip around 1.5 V peak. The PGA2310 runs on up to ±12 V (±12 V here), handles over 7 Vrms, steps in 0.5 dB, and changes gain only at zero crossings, so there is no zipper noise. Its logic inputs are TTL-threshold, so the 3.3 V XIAO drives it directly.
  • THAT 1246 / 1646 pair. The receiver drops 6 dB and the driver adds it back, so balanced-to-balanced is unity gain and the PGA sees a signal that fits comfortably. The 1646 is cross-coupled, so a TS plug on an output still gets the full signal instead of half.
  • Matrix instead of a routing switch. Four gains cost one extra PGA2310 but remove every analog switch, and they make mono-to-stereo, balance, true pan and mono-sum pure firmware.

Cost-down option

If cross-feed and mono-sum do not matter, drop U4 and the summers and put a DG419 analog switch in front of the second PGA channel: it picks the R receiver when a plug is present and the L receiver when it is not. That saves roughly $18 and one op-amp, at the cost of a small click on plug insertion unless firmware mutes around it.

The 5V pin is USB VBUS straight through (only the module's own 3.3 V regulator sits behind a diode), so it carries the bus 5 V out to the rest of the board, which is exactly what sheet 5 needs. The Philhower RP2040 Arduino core with Adafruit TinyUSB gives class-compliant USB MIDI. So yes, bus power works, with two conditions:

  • Plug into a real port or a powered hub. An unpowered hub shares one 500 mA allowance across every device on it, and a laptop running on battery may throttle its ports.
  • Expect the audio ground to be tied to the computer's ground. PS1 isolates the rails, but the XIAO and PGA share a ground, so the box's audio ground meets USB ground. If the same computer also drives the PA through an audio interface this is one ground and no problem. If the computer is only sending MIDI while the synths go to a separately earthed mixer, a hum loop is possible. The cure, if you hear it, is a TI ISO7762 digital isolator on the four SPI/mute lines and the two sense lines, with the PGA's 5 V logic taken from +12 V through a 78L05 instead of from USB. That floats the entire analog side from the computer for about $6 in parts.

Gain code per PGA channel is N = 192 + 2·dB, clamped to 0–255, with 0 meaning mute. Each PGA takes a 16-bit word, right channel byte first. With two chips daisy-chained the XIAO sends U4's word, then U3's, in one chip-select frame:

// a,d live in U3 (L,R); c,b live in U4 (L,R)
uint8_t code(float dB){ if (dB < -95.5f) return 0; return (uint8_t)constrain(192 + 2*dB, 1, 255); }

void writeMatrix(float a, float b, float c, float d){
  SPI.beginTransaction(SPISettings(1000000, MSBFIRST, SPI_MODE0));
  digitalWrite(CS, LOW);
  SPI.transfer(code(b)); SPI.transfer(code(c));   // U4: R byte, then L byte  (shifts through to U4)
  SPI.transfer(code(d)); SPI.transfer(code(a));   // U3: R byte, then L byte
  digitalWrite(CS, HIGH);
  SPI.endTransaction();
}

// mono mode: theta = pan/127 * PI/2;  a = vol*cos(theta); c = vol*sin(theta); b = d = mute

Build order and checks
  1. Power only. Fit U9, FB1, C11, PS1 and the filters, nothing else. Plug the USB cable into the computer and confirm roughly +12 / −12 V with a 330 Ω test load on each rail (unregulated: a volt or two high with no load). Put an inline USB current meter on the cable: expect well under 350 mA.
  2. XIAO. Load a TinyUSB MIDI sketch that blinks LED1 on any MIDI message. Check the box appears as a MIDI device on the computer and that the DIP switch selects the channel.
  3. Receivers and drivers. Fit U1, U2, U6, U7 and jacks. Temporarily jumper L_SE to L_SUM: a balanced test tone should come out at unity gain, and a TS plug on the input should still produce a balanced output.
  4. Matrix. Remove the jumper, fit U3, U4, U5. Write code 192 to all four gains and confirm unity, then mute (0) and confirm silence. Change gains while a tone is playing: with ZCEN high there should be no click.
  5. Plug sense. Watch D0 and D1 while inserting TS and TRS plugs; both must read high with any plug and low when empty.
